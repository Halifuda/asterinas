# Meso 06: `file_content_mutation` Architecture

## 1. Meso-Component Definition
- **Component**: `file_content_mutation`
- **Macro-Owner**: `ExfatInode(file)`
- **Responsibility**: Owns regular-file content and size mutation, including `write_at`, append growth, `resize` growth/shrink, initialized-data exposure, stream-shape persistence, mutation-side mapping synchronization, explicit fallocate-family refusal, and content-change timestamp triggers while importing allocator authority from `meso_02_free_space_accounting_and_discard` and volume anomaly posture from `meso_08_filesystem_sync_and_volume_state`.

## 3. Static Lock Boundaries
- **Expected Inlet State**:
  - `write_at`, append-style write mutation, `resize`, shrink/truncate, mutation-side page-fault handling, and fallocate refusal must enter through `ExfatFs state rwlock(Write/intend-mutate)` and the target file's `ExfatInode rwlock(Write)`.
  - Stream-shape changes must then sit behind the file `ExfatStream extent rwlock(Write)` before any FAT/bitmap allocation or free request is made.
  - Callers must not enter this meso while holding `ExfatFs allocator rwlock`; allocator authority is entered only after the file and stream mutation state is established in the frozen hierarchy.
  - File-scoped sync or filesystem-wide quiesce state may be observed as imported policy, but callers must not begin from `meso_07_file_sync_and_persistence` or `meso_08_filesystem_sync_and_volume_state` lower-level contexts.
- **Topology Placement**:
  - Highest lock level permitted to acquire internally: `Level 4` (`ExfatFs allocator rwlock`) for cluster allocation/free, bitmap changes, FAT backfill, and accounting updates requested through `meso_02_free_space_accounting_and_discard`.
  - Prohibited dependencies: `Cannot acquire ExfatFs state rwlock after entering an inode, stream, or allocator lock`; `cannot acquire another inode or directory mutation lock`; `cannot treat file-scoped fsync as part of this meso`; `cannot revise the frozen ExfatFs state -> ExfatInode -> ExfatStream extent -> ExfatFs allocator hierarchy`.

## 4. External structural interactions

- Requests cluster allocation/free, FAT update, Allocation Bitmap update, and `used_clusters` changes through the allocator authority owned by `meso_02_free_space_accounting_and_discard`; this meso owns file-stream mutation semantics, not global allocator truth.
- Coordinates with `meso_05_file_content_mapping_and_cached_io` through the shared stream-extent anti-race boundary: mapping consumes stable stream state, while this meso mutates that state under the write side of the boundary.
- Hands persistence of file-local dirty data and metadata to `meso_07_file_sync_and_persistence`; this meso defines mutation publication and timestamp-trigger obligations but does not own file-scoped `fsync`.
- Imports global `VolumeDirty`, `ClearToZero`, `MediaFailure`, and forced-shutdown posture from `meso_08_filesystem_sync_and_volume_state`; local content mutation must observe those states without redefining the volume-wide state machine.
- Coordinates timestamp trigger and on-disk timestamp family ownership with `meso_09_file_metadata_projection_and_update`; this meso triggers mtime/atime changes for content/length mutation, while metadata projection owns broader setter, timezone, and POSIX projection policy.
- Leaves namespace reachability, directory-entry slot movement, and parent directory mutation to `meso_04_directory_entry_mutation`; this meso may rewrite the target file's own Stream Extension and file-entry metadata but does not own create, unlink, rename, or parent-entry placement.
