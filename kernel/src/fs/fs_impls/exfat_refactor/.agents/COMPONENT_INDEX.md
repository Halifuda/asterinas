This file is owned by the main agent.
It is the canonical task board for the exFAT multi-agent project: both the refactor itself and the study of how far the workflow can be automated safely.

Rollback note (`2026-04-05`): the earlier post-`INOKEY` plan was intentionally discarded after it drifted into ownerless staging components rather than converging on stable owners.

Board-reset note (`2026-04-05`): the planned half of this board is rebuilt from [`WORKSPACE-ARCH-RESET/00_architect.md`](/home/halifuda/asterinas/kernel/src/fs/fs_impls/exfat_refactor/.agents/components/WORKSPACE-ARCH-RESET/00_architect.md). Allowed states:

- `Planned`
- `Architected`
- `Specified`

- `SerialChecked`
- `ConcurrencyImplementing`
- `ConcurrencyChecked`
- `Reviewing`
- `FinalChecked`
- `Accepted`
- `Blocked`

## Board Columns

This board tracks stable functional units only. It intentionally separates finished-system ownership from workflow ownership.

| Column | Meaning |
| --- | --- |
| `Final Owner` | The stable architectural owner in the finished system. This is the type or owner that should carry the behavior or state when the refactor converges. |
| `Landing Form` | How the unit lands inside that owner: validated value type, owner methods, owner-private helpers, owner-internal state, or trait impl. |
| `Boundary Kind` | Why the unit is allowed to be tracked as its own row: stable architectural boundary, independent validated value type, or historical maintenance slice kept only for record continuity. |
| `Scheduler Owner` | Workflow ownership for the row. This stays with the main agent unless the scheduling protocol changes. It is not the same thing as `Final Owner`. |
| `Code Budget` | Expected code-shape budget for the functional unit itself, not a promise that one packet or one creator owns the entire row. Work slices may be smaller. |
